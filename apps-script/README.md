# Connect Google Forms and Sheets

## Files

Create one Apps Script project owned by Valora's Workspace account. Copy `Code.gs`, generated `Domain.gs`, generated `Config.gs` and `appsscript.json` into it. Enable “Show appsscript.json manifest file” in project settings to edit the manifest. The bundle is generated by `npm run build:apps-script`; do not hand-edit it.

Create a restricted Google Sheet for event operations. It can be separate from the form's raw response sheet. The code creates normalized operational tabs automatically.

## Script Properties

| Key                               | Value                                                                      |
| --------------------------------- | -------------------------------------------------------------------------- |
| `SPREADSHEET_ID`                  | ID of the operational Google Sheet                                         |
| `API_SECRET`                      | 32+ random characters; same as Vercel `APPS_SCRIPT_SECRET`                 |
| `APP_URL`                         | HTTPS website origin, with no trailing slash                               |
| `FORM_ID`                         | Google Form ID, not a shortened public URL                                 |
| `FORM_EVENT_ID`                   | `valora-mun-2026` for the first event                                      |
| `MATRIX_APPROVED_valora-mun-2026` | `true` after reviewing all draft portfolios                                |
| `EMAIL_WORKER_URL`                | `https://your-domain/api/email/process`                                    |
| `EMAIL_WORKER_SECRET`             | Same as Vercel `CRON_SECRET`                                               |
| `FORM_FIELD_MAP`                  | Optional JSON mapping platform fields to your form's exact question titles |

A global `MATRIX_APPROVED=true` also works if all configured event matrices have been reviewed. Use per-event approval when adding events.

SMTP credentials stay in Vercel. Apps Script never sends email itself: it wakes the Nodemailer worker, which claims and acknowledges outbox entries through the authenticated adapter.

## Form questions

Use these titles or map them using `FORM_FIELD_MAP`:

- `Full Name`
- `School/Institution`
- `Class/Grade`
- `Email`
- `Contact Number`
- `MUN experience` — Beginner / Intermediate / Experienced
- `Preference 1`, `Preference 2`, `Preference 3` — WHO / UNGA / UNHRC / Lok Sabha / AIPPM / UNFCCC
- `UPI transaction/reference ID`
- `Payment confirmation` — a required confirmation beginning with “Yes” or “I confirm”

Do not collect country/portfolio preferences. Include your own genuine UPI QR and payment instructions in the form. Publish refund/cancellation, eligibility and consent requirements before accepting payment.

For example, if your questions have different titles:

```json
{
  "name": "Your full name",
  "email": "Email address",
  "payment_reference": "UPI UTR",
  "payment_confirmation": "I have made the payment",
  "preference_1": "First choice",
  "preference_2": "Second choice",
  "preference_3": "Third choice"
}
```

Question titles must be unique. Committee answers can use the category name or its configured ID. Distinct preferences and participant data are validated on import. The stable Google Form response ID makes trigger retries idempotent.

## Install

1. Run `setupValora()` from the editor and authorise the requested spreadsheet access. This creates the tables and the hidden committed-state tab.
2. Review/edit matrices through `/admin/settings`, then set the approval properties above.
3. Run `installFormTrigger()` and authorise Forms/trigger access. This installs a **Form submit** trigger, not a spreadsheet submit trigger. Do not manually run `onValoraFormSubmit()` without an event.
4. Deploy as a Web app, execute as the Workspace owner, allow endpoint access so the server can call it. Every operation still requires the shared `API_SECRET`; no unauthenticated read or mutation is permitted. Copy the deployment's `/exec` URL into Vercel `APPS_SCRIPT_URL`.
5. Set `DATA_PROVIDER=apps-script` and the corresponding secrets in Vercel, then redeploy.
6. After SMTP settings are configured in Vercel, run `installEmailWorkerTrigger()` to wake the worker each minute. This makes automatic retries independent of someone having the admin dashboard open.
7. Submit one controlled form response and confirm the pending registration appears in the dashboard. Check the actual UPI receipt before verifying. Then confirm allocation, email attachment and secure verification.

When you change the event seed or domain, rebuild the two generated files, paste the updated code, and create a new Web app deployment version while retaining the same deployment URL.

## Data and recovery

The domain allocates under `LockService.getScriptLock()`. All relevant state is read and changed inside that lock. This prevents parallel organisers/triggers from claiming the same portfolio.

Google Sheets has no multi-tab transaction. `_State` contains chunked versioned JSON snapshots. A single `STATE_VERSION` Script Property points to a complete snapshot only after its chunks are flushed. The current and previous snapshots are retained. Failed writes before commit leave the prior state authoritative. Participants/Registrations/etc. are human-readable projections refreshed after commit. A projection failure sets `PROJECTION_ERROR`; run `rebuildOperationalViews()` to repair the visible tabs from committed state.

Do not edit or delete `_State` or `STATE_VERSION`. Hiding a tab is not an access-control mechanism: restrict sharing of the entire spreadsheet. Do not expose raw response sheets, payment details, private links or secrets publicly. Keep regular spreadsheet backups plus a record of Script Properties in a secure administrator-controlled location.

Failed form imports are written to `ImportErrors` with the response ID and a safe error. Fix question mapping, invalid preferences or matrix approval, then run `retryFailedImports()`. It processes at most ten distinct unresolved responses per run and marks recovered errors resolved. Duplicate registration emails/transactions intentionally require organiser resolution instead of creating a second allocation.

The current trigger configuration uses one Google Form/event per installation. To run a subsequent event, add its source configuration, rebuild/redeploy the seed, update `FORM_ID` and `FORM_EVENT_ID`, and run `installFormTrigger()` again. For simultaneous events with separate Google Forms, install a separate trigger project configured for each form but use **one operational adapter project** for all writes; route each trigger's imported payload to that adapter's authenticated `import` endpoint so the shared lock remains authoritative. Do not run independent writers against the same Sheet.

Outbox delivery is performed by Nodemailer with leases and acknowledgement. Provider acceptance and datastore acknowledgement cannot form a single atomic SMTP transaction; a rare duplicate email is possible after an acknowledgement outage. E-ID and allocation remain unique.

## Website Razorpay checkout

The website now collects delegate details and preferences before opening Razorpay Checkout. The existing Google Form flow remains for legacy imports. Update **both** `Domain.gs` (generated by `npm run build:apps-script`) and `Code.gs`, then redeploy the web app; the new authenticated `settle-payment` action must be present for browser confirmations and webhooks to work. It validates captured payment evidence, matches the stored order/amount, and atomically confirms payment, allocates a committee and issues an E-ID. Configure Razorpay credentials/webhooks on the Next.js server, not in Apps Script. See the main README for setup and test-mode checks.
